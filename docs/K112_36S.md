# 36S — two KICMs on one daisy chain

## Hardware

- **BICM-A (K112)**: 24S — tap Teensy on X1 pins 9–13 (toward BECM).
- **BICM-B (12S)**: daisy out from A (pins 14–18 → next module 9–13).
- One **125 kbps** CAN tap sees both modules.

## Firmware

```bash
pio run -e teensy41_k112_36s -t upload
pio device monitor -b 115200
```

Expect **`cells=36 stable=Y`** and **`bicms=2/2`**.

Default CAN mapping (change in `include/BicmPackProfile.h` if your bus differs):

| BICM | IDs | Cells |
|------|-----|-------|
| A | `0x460` / `0x470` | 1–24 |
| B (burst) | `0x461` / `0x471` | 25–36 (if present on bus) |
| B (sparse) | `0x46D` `0x47D` `0x46E` `0x47E` | 25–27, 28–30, 31–33, 34–36 |

Firmware env **`teensy41_k112_36s`** enables sparse decode when `0x461`/`0x471` are absent.

Optional probe: **`teensy41_k112_48s`** — keeps accumulating `0x460`/`0x470` to 48 cells (see if both blocks share one burst).

After wiring B, run **`s`** (ID histogram). If B uses other IDs, edit `BicmSparseMap.h` or `BicmPackProfile.h` and rebuild.

## Balance TX (gated)

`0x300` / `0x310` packing for this 36S string lives in `include/K112BalanceMap.h` and is **not** VoltBMSV2's 4-module 6S/8S CMU map (that would collapse the 24S `0x460`/`0x470` burst into one byte).

| Flag | Behavior |
|------|----------|
| `BMS_CAP_BALANCE_TX=0` (default) | Monitor + keep-alive `0x200` only. `b` prints the would-be frames. |
| `=1` | TX `0x300` (DLC 8) then `0x310` (DLC 5) immediately before each `0x200`. |

Still **not** a production BMS.

## Charge TX + contactors (gated)

Elcon / TC on **CAN2 @ 250 kbit** (pins 0/1, 29-bit `0x1806E5F4`) and the precharge/contactor state machine are compiled. Flags stay 0:

| Flag | Serial dry-run | On the wire |
|------|----------------|-------------|
| `BMS_CAP_CHARGE_TX=0` | `g` prints `0x1806E5F4` | no CAN2 TX |
| `BMS_CAP_CONTACTOR_DRV=0` | `e` / `p` print intended PRE/MAIN+/MAIN− | FET gates stay LOW |

OUT2 is TE EV11 / K1KABNA (precharge), not a third EV200. `teensy41_k112_36s` stays `TELEMETRY_ONLY=1`. Weekend bench does not need charger or coils. See `docs/SAFETY.md`, `docs/WIRING.md`, and `/workspace/teryx/CHARGE_CONTACTOR_NOTE.md`.
