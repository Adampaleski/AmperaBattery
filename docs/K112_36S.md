# 36S — two KICMs on one daisy chain

## Hardware

- **BICM-A (K112)**: 24S — tap Teensy on X1 pins 9–13 (toward BECM).
- **BICM-B (12S)**: daisy out from A (pins 14–18 → next module 9–13).
- One **125 kbps** CAN tap sees both modules.

## Firmware

```bash
pio run -e teensy41_k112_36s -t upload
pio device monitor -b 115200
```

Expect **`cells=36 stable=Y`** and **`bicms=2/2`**.

Default CAN mapping (change in `include/BicmPackProfile.h` if your bus differs):

| BICM | IDs | Cells |
|------|-----|-------|
| A | `0x460` / `0x470` | 1–24 |
| B (burst) | `0x461` / `0x471` | 25–36 (if present on bus) |
| B (sparse) | `0x46D` `0x47D` `0x46E` `0x47E` | 25–27, 28–30, 31–33, 34–36 |

Firmware env **`teensy41_k112_36s`** enables sparse decode when `0x461`/`0x471` are absent.

Optional probe: **`teensy41_k112_48s`** — keeps accumulating `0x460`/`0x470` to 48 cells (see if both blocks share one burst).

After wiring B, run **`s`** (ID histogram). If B uses other IDs, edit `BicmSparseMap.h` or `BicmPackProfile.h` and rebuild.

## Not included

This build still does **not** send balance (`0x300`) or charge commands. See `docs/SAFETY.md`.
