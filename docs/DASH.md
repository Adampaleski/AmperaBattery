# Teryx dash (in-vehicle cluster)

`tools/dash.html` is the standalone, read-only dash, styled after OEM digital EV clusters like Tesla. The sim's **Cluster** tab runs the same component (`sim/dash.js`). Both files are generated by `scripts/build_bms_sim_html.sh`. The dash never sends commands.

## Styles

Switch styles with the **Style ▾** menu, top right. The choice is saved in localStorage `teryxDashStyle`.
- **Digital:** big numerals.
- **Analog:** needle gauges for kW (regen arc in green), mph and battery %.
- **Minimal:** speed, power, range and battery only.
- **Night:** dimmed.

## Data source

Open the Style menu, or use `?src=`. The choice is saved in localStorage `teryxDashSrc`.

| Source | How |
|---|---|
| `sim` | `BroadcastChannel('teryx-dash')` from the sim's Cluster tab (same origin), or `postMessage` from the sim's "Open full-screen dash window" button |
| `http://…/api/status` | Polls every 500 ms. This is the ESP32 gateway's existing `GET /api/status` (teryx-ev-hub). |
| `ws://…` | One JSON status per message. **No WebSocket emitter exists yet (PROPOSED).** |
| `none` | Everything shows "—" |

Readings come only from the status object. A frame older than 3 s counts as stale, and the dash then shows **"—" with an amber dot**. A missing or null field shows the same way. Nothing is invented.

Values the dash computes are tagged on screen:
- **RPM estimate:** used only when `drive.rpm` is null. It is speed × ≈122.5 RPM per mph: 16/32 sprockets × 4.375 diff = 8.75 (SOURCED) on 24" stock tires (SOURCED: Adam). 55 mph ≈ 6740 RPM, above the PROPOSED 6000 RPM High cap, so the model tops out near 49 mph.
- **Range:** uses `energy.rangeMiEst` when the source sends it. Otherwise it is SoC × pack kWh ÷ Wh/mi.
  - Wh/mi is the last-5-mi average, then the trip average, then **350 Wh/mi ASSUMED**.
  - Pack kWh is `energy.packKWh`, otherwise **23.3 kWh ASSUMED** (36 × 3.6 V × 180 Ah).
- **Trip miles, kWh used and kWh regen** are integrated in the browser from `speedMph` and `packV × packA`. They are saved in localStorage, and the trip panel has a reset. The last frame is held until it goes stale, so live feed gaps of under 3 s are integrated as if the value held.

## Schema

STATUS_SCHEMA v1 (teryx-ev-hub/docs/STATUS_SCHEMA.md) plus the additive fields below. All of them are optional; when one is missing, that reading shows "—".

| Field | Type | Meaning |
|---|---|---|
| `src` | string | `"sim"` shows the SIMULATOR DATA badge |
| `bms.currentVerified` | bool | false shows the "LEM uncalibrated" tag (`CURRENT_SENSE_ENABLE=0`) |
| `bms.socState` / `bms.socWhy` | string | BmsCore::Soc state: unknown, anchored or counting |
| `bms.tempsVerified` | bool | false: pack temperature shows "—" (`TEMPS_VERIFIED=0`) |
| `bms.lemImbalance` | bool | Tell-tale |
| `drive.gear` | `P\|R\|L\|M\|H` | Gear. Not wired: Kelly speed and reverse inputs UNVERIFIED |
| `drive.speedSource` | string | Tag shown next to mph (e.g. "sim model") |
| `drive.limp`, `drive.regenOk`, `drive.powerAllowedPct` | bool/num | BMS cutback state (print-only) |
| `energy.packKWh` | number | Usable pack energy, used for range |
| `aux12v.loads` | `{lights,fan,pump,alarm,speakers}` bool, `seatDriver`/`seatPassenger` 0–3 | Tell-tales and seat buttons. All 12 V loads are PROPOSED |
| `aux12v.loadA` / `loadAEstimate` | number / bool | Total 12 V load. The sim sums ESTIMATE currents: pump 3.5, fan 8, lights 10, speakers 10, alarm 0.5, seats 4.5 A × level/3 |
| `coolant` | `{wired,pumpOn,flowOk,tempC}` | Kelly coolant loop. **No live source.** Coolant tell-tale fires on `flowOk:false` or `tempC ≥ 60` (PROPOSED threshold) |

The firmware's `HubStatus` emitter doesn't send these extra fields yet. Adding them is firmware work and needs the crew to agree first.

## Build 15: why an action is refused, brake wake, phone key, PIN to Drive (Adam t284)

**Pop-up, not a fault.** When a driver request is refused (throttle, wake, shift, changing a drive setting), the sim and the dash show a short pop-up that lists the reasons in plain words, most important first. Example: key on with the parking brake set and the throttle pressed gives "Throttle blocked: Parking brake is on, release it to drive". This never latches a fault and never writes the fault log. One list decides it: `include/BmsCore` facts plus the sim interlocks go through `blockReasons()` in `include/BlockReasons.h` (host test `scripts/test_block_reasons.cpp`; wasm `sim_block_mask` / `sim_block_text`). `simInfo.block.{drive,wake,shift,setting}` carries the same text to dash.html.

**Brake wake (PROPOSED).** With "Brake wakes" on (Sim tab), pressing the brake to full travel (≥98 %) for 1 s with the key off turns the machine on. The dash shows "Hold brake… waking", then "Waking…". If it can't wake (e-stop latched, charger plugged in, …) it says "Can't wake:" and the reasons. It works from the dash.html SIMULATOR panel brake slider too.

**Phone nearby (PROPOSED / UNVERIFIED).** The Sim tab has a "Phone nearby (Bluetooth)" toggle and the dash shows a phone icon. In the car this would be a future ESP32 that only reads the phone's Bluetooth presence: read-only, outside every safety path. In the sim it is only a simulated input.
- Key off: no setting can be changed.
- Key on, no phone: drive settings need the PIN.
- Display settings (night mode) are always open.
- Kid mode can be entered without the PIN; leaving it needs the PIN.

**PIN to Drive (PROPOSED, off by default).** When on, the throttle is blocked until the phone is seen or the PIN is entered, and the pop-up says "Enter PIN or bring phone to drive". Turning the setting on or off needs the PIN or the phone. (Build 15 asked you to set a PIN the first time; Build 18 replaced that with the 0000 default below.)

## Build 18: security (PIN to Drive, lock, master alert)

**Root cause fixed.** Before Build 18 the sim set "drive OK" whenever the phone was seen and only cleared it at key-off, the pad only opened on brake wake or the first throttle press, and two flags could disagree. Now one rule is checked live on every loop and never latched: drive allowed = PIN to Drive off, OR phone nearby right now, OR PIN entered this key cycle (PROPOSED).
- While locked, every drive action (throttle, shift, drive settings) opens the PIN pad. Display and night settings stay open.
- Phone walks away while moving: warning only, drive is NOT cut; the gate locks at 0 mph or in Park.
- 5 wrong PINs lock the pad for 30 s.
- Walk-up: a brake tap with the key on and no phone opens the pad (30 s timeout).
- With the phone nearby no PIN is asked, except Kid exit, which always needs the PIN. Kid entry is free (sim only, see below).
- Change PIN: current PIN, then the new PIN twice; a mismatch changes nothing.
- Master alert (PROPOSED): amber light and a WebAudio chime with mute (Display settings). Real 12 V buzzer is LATER (MCP23017 bit 13, PROPOSED).

**Default PIN: DECIDED (Adam, 2026-10-23).** The default PIN is 0000 and the dash shows a "PIN is still 0000, change it" reminder. There is no forced first-time PIN setup. When PIN to Drive moves to firmware (after first drive, LATER), the firmware follows the same rule: default 0000 + change-your-PIN reminder, no forced setup. This supersedes the firmware `NO_PIN_SET` rule in `include/DriveProfile.h` (firmware code not changed in Build 18).

**Known sim / firmware difference (UNVERIFIED until the firmware work):** the sim lets you enter Kid mode with no PIN. Today's firmware `DriveProfile` returns `NO_PIN_SET` for Kid when no PIN is stored; that goes away with the DECIDED 0000 default when the firmware PIN work is done.

## Build 15: iPhone / in-page sim engine

iOS Safari freezes background tabs, so a dash fed by a Sim tab in another tab goes stale. dash.html?src=sim can now run the simulator itself, in a hidden frame inside the page:
- `?engine=auto` (default): use a Sim tab if one answers; if none answers within 2.5 s, or the Sim tab goes quiet, start the engine in this page. The SIMULATOR panel shows "Sim engine: running in this page (no Sim tab needed)".
- `?engine=page`: always run in this page. `?engine=tab`: never (old behaviour).
- "Run sim in this page" starts it by hand. "Full sim controls" shows the whole simulator over the dash; "✕ Back to dash" hides it (it keeps running).
- PIN pads and pop-ups from the engine show on the dash and work by touch.
- Touch: every control is at least 44 px on screen, `touch-action: manipulation` (no double-tap zoom), safe-area padding for the notch, number boxes use 16 px text (iOS won't zoom in), tapping a warning light shows what it means.
- Checked headless at 390×844 and 844×390 by `scripts/test_iphone.py`. NOT checked on a real iPhone: Safari tab freezing, notch insets, tap feel, the frame + messaging on the published (gist) host.

## Data source per gauge

| Gauge | Source | Status |
|---|---|---|
| Speed | Kelly CAN 0x0CF11E05 RPM × gearing | `BMS_CAP_KELLY_RX=0`, so "—" live. The sim uses its own model. |
| RPM | Kelly CAN 0x0CF11E05 b0–b1, else estimated from speed | RX off |
| Power kW / regen | Pack V (BICM sum) × LEM A + LEM B | LEM sign and zero calibration TODO; `CURRENT_SENSE_ENABLE=0` |
| Battery % | BmsCore::Soc coulomb count on the LEMs | Unknown until a full-charge anchor; capacity UNVERIFIED |
| Range, Wh/mi, trip | Computed in the dash (see above) | Estimates |
| Gear | Kelly switch inputs / PROPOSED Teensy tap | Not wired |
| Pack V/A, cell min/max | BICM over CAN3/CAN1; LEM A0/A1 | Cells are live on the bench |
| Temps | Pack: BICM thermistors (`TEMPS_VERIFIED=0`). Kelly and motor: CAN 0x0CF11F05 | Not decoded |
| Tell-tales | BMS faults/latched, contactor states, derates, `aux12v.loads`, `coolant` | Loads and coolant PROPOSED |
| Fault banner | `faults[]` with `level:"fault"`; Acknowledge hides it until the fault set changes | — |

## Cooling (PROPOSED)

- The Kelly W3-GT2 loop uses the **stock Teryx radiator** plus a Bosch 12 V pump on an unassigned Teensy FET. The pump runs whenever the key is on.
- The radiator fan runs through a 12 V relay driven by the Teensy (pin unassigned). It comes on at about 40 °C, using Kelly temperature (CAN 0x0CF11F05, not decoded yet) or a coolant sensor (none fitted). This replaces the earlier 45 °C placeholder.
- There's no flow or coolant-temperature sensor yet, so the coolant tell-tale has no live source.
- There is no cabin heater.

## Seat heaters (PROPOSED)

- Tesla-style buttons for driver and passenger. Each tap steps Off → Low → Med → High, lighting 1, 2 or 3 red bars; holding the button turns it off.
- Levels would be MOSFET PWM at 33 / 66 / 100 % (PROPOSED). They're probably an aftermarket kit, and whether it's single- or two-stage is UNVERIFIED.
- About 4–5 A per seat at 12 V on a 10 A fuse (ESTIMATE).
- On the standalone dash the buttons are display-only. Nothing is sent, because no output is wired.
