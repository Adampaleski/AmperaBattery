# One K112 BICM = 24S sub-pack (your diagram)

## Physical vs CAN

| Layer | What it is |
|-------|------------|
| **Physical** | One **K112** Battery Interface Control Module in the pack |
| **Sense wiring** | Connectors **X1–X4** to battery modules (e.g. 6S + 12S + 6S = **24 cells**) |
| **CAN bus** | The K112 **broadcasts** those cells as many CAN frames (IDs `0x460`–`0x473`, temps `0x7E0+`) |

You do **not** need four separate BICM boards for 24 cells — one K112 can monitor the whole section.

## Wiring (your diagram)

- **K112A X1 pins 9–13** = toward BECM on the daisy chain (5V, GND, two data lines, signal).  
- You do **not** need K112B/C/D on the bus to see 24 cells from **one** K112 that senses all of them.

## Expected CAN (one K112, 24 cells)

Reference captures show a **burst** (`0x4E0` … `0x500`) with **many** `0x460` and `0x470` frames (mix of 6- and 8-byte length). Each frame adds more cell voltages **in order** — not only one `0x460` + one `0x470`.

IDs like `0x461`–`0x463` appear when **several** BICMs are on the chain (K112B, C, D). With only K112A, expect mostly **`0x460` / `0x470`** repeating.

Firmware env: **`teensy41_k112_24s`** — accumulates all `0x460`/`0x470` frames per burst into cells 1–24.
